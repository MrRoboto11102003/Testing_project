# arnio.pipeline.register_step
def register_step(name: str, fn: Callable, overwrite: bool = False):
    """Register a custom Python pipeline step.

    Parameters
    ----------
    name : str
        Name of the step for use in pipelines.
    fn : Callable
        Function to call for this step. Should accept (df, **kwargs) and return modified df.
    overwrite : bool, default False
        If True, allows replacing an existing custom Python step with the same name.
        Cannot be used to overwrite built-in C++ steps.

    Raises
    ------
    ValueError
        If the step name conflicts with a built-in C++ step name, or if the name
        conflicts with an existing custom Python step and `overwrite` is False.

    Examples
    --------
    >>> def custom_clean(df, threshold=0.5):
    ...     return df.dropna(thresh=threshold)
    >>> ar.register_step("custom_clean", custom_clean)
    # Overwriting an existing custom step intentionally
    >>> def new_custom_clean(df):
    ...     return df
    >>> ar.register_step("custom_clean", new_custom_clean, overwrite=True)
    """
    with _REGISTRY_LOCK:
        if not isinstance(name, str) or not name or not name.strip():
            raise ValueError("parameter 'name' must be a non-empty string")
        if not callable(fn):
            raise TypeError("parameter 'fn' must be a callable object")
        if not isinstance(overwrite, bool):
            raise TypeError(
                f"parameter 'overwrite' must be a bool, not {type(overwrite).__name__}"
            )

        if name.startswith(f"{_BUILTIN_STEP_NAMESPACE}{_STEP_NAMESPACE_SEPARATOR}"):
            raise ValueError(
                f"Cannot register '{name}': "
                f"'{_BUILTIN_STEP_NAMESPACE}{_STEP_NAMESPACE_SEPARATOR}' "
                "is reserved for built-in pipeline steps."
            )
        if name in _STEP_REGISTRY:
            raise ValueError(
                f"Cannot register '{name}': conflicts with built-in C++ step. "
                f"Use a different name."
            )
        if name in _BUILTIN_PYTHON_STEP_REGISTRY:
            raise ValueError(
                f"Cannot register '{name}': conflicts with built-in Python step. "
                f"Use a different name."
            )
        if name in _DEPRECATED_STEP_ALIASES:
            raise ValueError(
                f"Cannot register '{name}': that name is reserved as a deprecated "
                "pipeline step alias."
            )
        if name in _PYTHON_STEP_REGISTRY and not overwrite:
            raise ValueError(
                f"Step '{name}' is already registered as a custom Python step. "
                "To intentionally overwrite it, set 'overwrite=True'."
            )
        _PYTHON_STEP_REGISTRY[name] = fn

# arnio.pipeline.reset_steps
def reset_steps() -> None:
    """Restore the Python pipeline registry to built-in steps only."""
    with _REGISTRY_LOCK:
        _PYTHON_STEP_REGISTRY.clear()
        _PYTHON_STEP_REGISTRY.update(_BUILTIN_PYTHON_STEP_REGISTRY)

### arnio.pipeline.register_step

# Notes: `arnio.pipeline.register_step(name, fn, overwrite=False)`

## 1. Purpose
- Adds a custom Python step to the global registry `_PYTHON_STEP_REGISTRY`.
- After that, `ar.pipeline(frame, [(name, kwargs)])` can use the step by name.
- Returns `None`.

## 2. Inputs
- `name`: must be a `str` that is non-empty and not whitespace-only.
  - It is **not** stripped or lower-cased. `" foo "` is stored exactly as given.
  - Non-str values such as `123` or `None` raise **ValueError**, not TypeError.
- `fn`: anything for which `callable()` is true (function, lambda, class, object with `__call__`).
  - Its signature is not checked at registration time.
- `overwrite`: must be exactly a `bool` (`isinstance` check).
  - `0`, `1` and `"yes"` are rejected.
  - `overwrite=True` with a brand-new name is fine and simply registers it.
- Reserved names, from module constants:
  - **Prefix `"builtin:"`** (`_BUILTIN_STEP_NAMESPACE + ":"`) is reserved.
    - The check is case-sensitive: `"Builtin:x"` and `"builtin"` are allowed.
  - **C++ steps** (`_STEP_REGISTRY`): drop_nulls, drop_columns, select_columns, keep_rows_with_nulls, fill_nulls, validate_columns_exist, drop_duplicates, drop_constant_columns, drop_empty_columns, clip_numeric, winsorize_outliers, normalize_minmax, strip_whitespace, hash_columns, parse_bool_strings, normalize_case, normalize_unicode, rename_columns, cast_types, round_numeric_columns, combine_columns, slugify_column_names, trim_column_names, clean_column_names.
  - **Built-in Python steps** (`_BUILTIN_PYTHON_STEP_REGISTRY`, filled at import): standardize_missing_tokens, coalesce_columns, normalize_whitespace, filter_rows, drop_columns_matching, rename_columns_matching, safe_divide_columns, replace_values.
  - **Deprecated aliases** (`_DEPRECATED_STEP_ALIASES`): empty by default. Only the private `_register_deprecated_step_alias` adds to it.

## 3. Raises
Checks run in this order while holding `_REGISTRY_LOCK`. Use `pytest.raises(..., match=re.escape(msg))`, because the messages contain `.`, `(`, `'` and `=`.

1. **Bad name** → `ValueError("parameter 'name' must be a non-empty string")`
   - Triggers: `register_step("", f)`, `register_step("   ", f)`, `register_step(123, f)`.
2. **Bad fn** → `TypeError("parameter 'fn' must be a callable object")`
   - Trigger: `register_step("x", None)`.
3. **Bad overwrite** → `TypeError(f"parameter 'overwrite' must be a bool, not {type(overwrite).__name__}")`
   - Trigger: `register_step("x", f, overwrite=1)` gives `"... not int"`.
4. **Reserved prefix** → `ValueError(f"Cannot register '{name}': 'builtin:' is reserved for built-in pipeline steps.")`
   - Trigger: `register_step("builtin:foo", f)`.
5. **C++ name** → `ValueError(f"Cannot register '{name}': conflicts with built-in C++ step. Use a different name.")`
   - Trigger: `register_step("drop_nulls", f)`. Raised even with `overwrite=True`.
6. **Built-in Python name** → `ValueError(f"Cannot register '{name}': conflicts with built-in Python step. Use a different name.")`
   - Trigger: `register_step("filter_rows", f, overwrite=True)`. Overwrite does not help.
7. **Deprecated alias** → `ValueError(f"Cannot register '{name}': that name is reserved as a deprecated pipeline step alias.")`
   - Not reachable through the public API.
8. **Duplicate custom name without overwrite** → `ValueError(f"Step '{name}' is already registered as a custom Python step. To intentionally overwrite it, set 'overwrite=True'.")`
   - Trigger: register `"my_step"` twice.

The order matters in these cases:
- `register_step(123, None)` → name ValueError (name is checked first).
- `register_step("drop_nulls", None)` → fn TypeError (fn is checked before the conflict checks).
- `register_step("drop_nulls", f, overwrite="x")` → overwrite TypeError.
- `register_step("builtin:drop_nulls", f)` → reserved-prefix message, not the C++ message.

## 4. Returns and guarantees
- Returns `None`.
- On success, `_PYTHON_STEP_REGISTRY[name] = fn`.
- With `overwrite=True` the new fn replaces the old one, and the pipeline uses the new fn.
- On any error the registry is unchanged:
  - A failed duplicate registration keeps the original fn.
  - A failed reserved-name registration adds nothing.

## 5. Side effects
- Mutates module-global state that persists across tests.
- `ar.list_steps()` (sorted union of C++ and Python names) then includes `name`.
- Clean up with `ar.unregister_step(name)` or `ar.reset_steps()`; the latter restores only the 8 built-in Python steps. An autouse fixture that calls `reset_steps()` after each test is recommended.

## 6. How a registered step behaves in `pipeline` (observable effects)
- The step is called as `fn(df, **kwargs)`.
  - `df` is a pandas DataFrame: for custom steps, a writable copy of a DataFrame subclass.
  - If `fn`'s signature has a parameter named `context` and kwargs do not supply one, a `PipelineContext(step_name, step_index, total_steps, dry_run)` is injected.
- It must return a `pd.DataFrame`. Otherwise:
  - Returning `None` → `TypeError("Custom pipeline step '{name}' returned None. Steps must return a pandas DataFrame.")`
  - Returning e.g. a list → `TypeError("Custom pipeline step '{name}' returned 'list' instead of a pandas DataFrame. Steps must return a pandas DataFrame.")`
- If `fn` raises, the exception is wrapped as `PipelineStepError(name, e)`, chained `from e`.
  - The message format is defined in `arnio.exceptions`, which is not shown. Assert only the type and `__cause__`.
- Pitfall: if `fn.__module__` starts with `"arnio.cleaning"`, the step is treated as built-in, even under a new alias.
  - Example: `register_step("my_filter", cleaning.filter_rows)`.
  - Its errors are re-raised raw (not wrapped).
  - It also appears in `get_builtin_step_signatures()`.
  - Plain user functions never appear there.

## 7. Rules from docstrings and comments
- Overwrite is meant only for replacing custom Python steps. It "Cannot be used to overwrite built-in C++ steps" (and in code, not built-in Python steps either).

## 8. Testing hints
```python
import re, pytest, arnio as ar, pandas as pd
from arnio.pipeline import register_step, list_steps, reset_steps, unregister_step

def f(df): return df
register_step("my_step", f)
assert "my_step" in list_steps()
out = ar.pipeline(ar.from_pandas(pd.DataFrame({"a": [1, 2]})), [("my_step",)])
assert ar.to_pandas(out)["a"].tolist() == [1, 2]
```
- To test overwrite:
  1. Register `g = lambda df: df.assign(b=1)` with `overwrite=True`.
  2. Run the pipeline.
  3. Check that the output has column `"b"`.
- To test that a failed duplicate leaves the old fn in place, check the pipeline output or `arnio.pipeline._PYTHON_STEP_REGISTRY["my_step"] is f`.
- Always use unique custom names, and reset the registry after each test.
- Do not assume `ar.register_step` exists at top level. Importing from `arnio.pipeline` is the safe choice.
- Do not expect a whitespace-padded name to be stripped: after `register_step(" s ", f)`, `" s "` is in `list_steps()` and `"s"` is not.

### arnio.pipeline.reset_steps

# Notes for `arnio.pipeline.reset_steps`

## 1. Purpose
- Restores the global Python step registry (`_PYTHON_STEP_REGISTRY`) to the built-in Python steps captured at import time.
- Removes every user-registered custom step.
- Re-adds any built-in Python step that was removed from the private dict.

## 2. Inputs
- Takes no parameters. `reset_steps(1)` raises a plain Python `TypeError`, because the signature is `reset_steps() -> None`.
- Full body:
  ```python
  with _REGISTRY_LOCK:
      _PYTHON_STEP_REGISTRY.clear()
      _PYTHON_STEP_REGISTRY.update(_BUILTIN_PYTHON_STEP_REGISTRY)
  ```
- `_BUILTIN_PYTHON_STEP_REGISTRY` is filled once, at module load, by `_BUILTIN_PYTHON_STEP_REGISTRY.update(_PYTHON_STEP_REGISTRY)`. At that point the registry holds exactly these 8 entries, in this insertion order:
  - `standardize_missing_tokens` → `cleaning.standardize_missing_tokens`
  - `coalesce_columns` → `cleaning.coalesce_columns`
  - `normalize_whitespace` → `cleaning.normalize_whitespace`
  - `filter_rows` → `cleaning.filter_rows`
  - `drop_columns_matching` → `cleaning.drop_columns_matching`
  - `rename_columns_matching` → `cleaning.rename_columns_matching`
  - `safe_divide_columns` → `cleaning.safe_divide_columns`
  - `replace_values` → `cleaning.replace_values`

## 3. Raises
- It raises nothing itself; the only failure is a `TypeError` if you pass arguments.

## 4. Returns and guarantees
- Returns `None`.
- After the call, `_PYTHON_STEP_REGISTRY` has exactly the 8 names above, each mapped to the original `arnio.cleaning` function object.
- It is the same dict object as before, because the code calls `clear()` then `update()` rather than rebinding the name.
- It does not touch:
  - `_STEP_REGISTRY`, the 24 C++ steps;
  - `_DEPRECATED_STEP_ALIASES`;
  - `_BUILTIN_PYTHON_STEP_REGISTRY` itself.
- After a reset, `list_steps()` returns `sorted(24 C++ names + 8 Python names)`. That is 32 names with no overlap. The C++ names are:
  - drop_nulls, drop_columns, select_columns, keep_rows_with_nulls, fill_nulls, validate_columns_exist
  - drop_duplicates, drop_constant_columns, drop_empty_columns
  - clip_numeric, winsorize_outliers, normalize_minmax
  - strip_whitespace, hash_columns, parse_bool_strings, normalize_case, normalize_unicode
  - rename_columns, cast_types, round_numeric_columns, combine_columns
  - slugify_column_names, trim_column_names, clean_column_names

## 5. Side effects
- It mutates process-global registry state under the non-reentrant `threading.Lock`.
- `pipeline()` releases the lock before running steps, so calling `reset_steps()` from inside a step does not deadlock. Avoid it anyway.
- It writes no files and mutates no frames.

## 6. Branches and edge cases
There is no branching in the function. The scenarios worth testing are:
- **Custom step removed.** Before reset, `register_step("my_step", f)` succeeds and `"my_step" in list_steps()` is True. After reset, `"my_step" not in list_steps()`.
- **Custom step no longer usable in a pipeline.** After reset, `ar.pipeline(frame, [("my_step",)])` raises `UnknownStepError`. The error comes from `_validate_pipeline_steps`, before any step runs. `UnknownStepError` subclasses `ArnioError`.
  - Its message format lives in `arnio/exceptions.py`, which is not shown. Do not assert the message text.
- **Re-registering after reset.** Before reset, a second `register_step("my_step", f)` without `overwrite` raises `ValueError` with exactly: `"Step 'my_step' is already registered as a custom Python step. To intentionally overwrite it, set 'overwrite=True'."`. After reset, the same call succeeds with no error.
- **Overwritten custom step.** `register_step("my_step", f)` then `register_step("my_step", g, overwrite=True)`, then reset: the name is gone.
- **Built-in Python step restored.** You cannot remove one through the public API:
  - `unregister_step("filter_rows")` raises `ValueError("Cannot unregister built-in step 'filter_rows'. Only custom user-registered steps can be unregistered.")`.
  - `register_step("filter_rows", f)` raises a `ValueError` starting `"Cannot register 'filter_rows': conflicts with built-in Python step."`.
  - To test restoration, delete it from the private dict: `del pm._PYTHON_STEP_REGISTRY["filter_rows"]`, then reset. Afterwards `"filter_rows" in list_steps()` and `pm._PYTHON_STEP_REGISTRY["filter_rows"] is ar.cleaning.filter_rows` (or `pm.cleaning.filter_rows`).
- **Idempotent.** Calling it twice in a row, or on an already clean registry, leaves the same 8 entries.
- **Multiple custom steps.** Register `a`, `b`, `c`, then reset: all are removed and all 8 built-ins remain.

## 7. Rules from comments/docstrings
- Docstring: "Restore the Python pipeline registry to built-in steps only."
- So the result is built-ins only: no leftover custom steps, and no missing built-ins.

## 8. Testing hints
- Get the module object safely, because `ar.pipeline` is probably the *function*, which shadows the submodule:
  ```python
  import importlib
  pm = importlib.import_module("arnio.pipeline")
  reset_steps, register_step, list_steps = pm.reset_steps, pm.register_step, pm.list_steps
  ```
  Avoid `import arnio.pipeline as pm`; it may bind the function.
- Use an autouse fixture that calls `reset_steps()` before and after each test, so global state does not leak between tests.
- A minimal custom step: `def my_step(df): return df`. Register it under a unique name such as `"my_custom_step_xyz"`.
- Build frames with `ar.from_pandas(pd.DataFrame({"a": [1, 2, 3]}))`.
- Assert each part separately, so a regression that only clears, or only restores, is caught:
  - (a) the custom name is absent;
  - (b) all 8 built-in Python names are present, e.g. `set(BUILTIN_PY) <= set(list_steps())`;
  - (c) `len(list_steps()) == 32` after reset;
  - (d) `pm._PYTHON_STEP_REGISTRY.keys() == set(BUILTIN_PY)`.
- Assert `reset_steps() is None`.
- Use the registry-identity check `pm._PYTHON_STEP_REGISTRY is` (the same object as before the call) only if you accept testing a private detail. It is true on the current code.
- Do not run the built-in Python steps (`filter_rows` etc.) to prove they are restored. Their kwargs and semantics live in `cleaning.py`, which is not shown. Check membership and identity instead.
- Do not assert on the text of `UnknownStepError`; its constructor is not shown.
- `list_steps()` output is sorted, so compare with `sorted(...)` or as sets.
