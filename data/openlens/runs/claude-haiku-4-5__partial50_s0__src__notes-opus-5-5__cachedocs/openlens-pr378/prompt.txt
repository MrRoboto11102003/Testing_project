## What is openlens?

openlens is a desktop application for designing and analyzing **glass optical
lenses and multi-element systems**. Whether you're a student learning optics, an
engineer designing optical systems, or a hobbyist exploring lens physics,
openlens provides an intuitive interface to:

- Design single lenses or assemblies with precise physical parameters
- Calculate first-order properties with thick-lens and paraxial models
- Experiment with different glass materials, surface profiles, and geometries
- Assign camera mounts and compute working flange distance
- Store and manage lenses, assemblies, and tolerance sets in SQLite
- Trace rays and inspect aberrations, spots, PSF/MTF, and wavefront error
- Export mechanical and manufacturing data as STL, STEP, or ISO 10110 drawings

## Installation

### Standalone executables (no Python required)

Every [release](https://github.com/pmaasz/openLens/releases/latest) includes
standalone builds for the desktop platforms:

| Platform | Download |
|----------|----------|
| Windows | `OpenLens-<version>-Windows.exe` |

| macOS (Intel) | `OpenLens-<version>-macOS-x64.zip` |
| Linux | `OpenLens-<version>-Linux` |

Unzip a macOS download and drag `OpenLens.app` to Applications. The builds are
not code-signed, so the first launch needs **right-click -> Open** (or

downloaded file executable with `chmod +x`.

1. **Clone or download the repository:**
   ```bash
   git clone <repository-url>
   cd openLens
   ```

2. **Set up virtual environment (recommended):**
   ```bash
   # Create virtual environment
   python3 -m venv venv

   # Activate virtual environment
   # On Linux/macOS:
   source venv/bin/activate

   # On Windows:
   venv\Scripts\activate
   ```

3. **Install OpenLens and optional dependencies:**

   ```bash
   # Install the package and its required PySide6 dependency
   pip install -e .

   # Full plotting and numerical features (recommended)
   pip install -e .[visualization]
   ```

   **For advanced features:**
   ```bash
   pip install scipy Pillow
   ```

   **Or install all optional dependencies:**

   ```bash
   python3 --version
   # Should show Python 3.10 or higher
   ```

   ```bash
   # GUI version (recommended)
   python3 -m openlens

   # OR CLI version
   python3 -m openlens.lens_editor
   ```

6. **When done, deactivate virtual environment (if used):**
   ```bash
   deactivate
   ```

## Troubleshooting

### Issue: "No display name and no $DISPLAY environment variable" / Qt platform plugin errors

This occurs when running on a headless server or via SSH without X11 forwarding.

**Solutions:**
- **If using SSH**: Connect with X11 forwarding: `ssh -X user@host`
- **If running locally**: Ensure your display server is running (restart your desktop environment if needed)
- **For remote headless servers**: Use a virtual display:
  ```bash
  sudo apt-get install xvfb
  xvfb-run python3 -m openlens
  ```
  or force Qt's offscreen platform for testing:
  ```bash
  QT_QPA_PLATFORM=offscreen python3 -m openlens
  ```
- **WSL users**: Install an X server like VcXsrv or X410, then:
  ```bash
  export DISPLAY=:0
  python3 -m openlens
  ```

### Issue: PySide6 not found

**Error:** `ModuleNotFoundError: No module named 'PySide6'`

**Solution:**
```bash
pip install PySide6
# or
pip install -r requirements.txt
```

### Issue: Lenses not saving

**Solution:**
- Check write permissions in the directory
- Ensure `openlens.db` is not locked by another process
- Check disk space

### Issue: 3D visualization not working

**Solution:**
```bash
# Install required dependencies
pip install matplotlib numpy

# Or if using venv:
source venv/bin/activate
pip install matplotlib numpy
```

## First lens

```python
from openlens.lens import Lens

lens = Lens(
    name="Biconvex demo",
    radius_of_curvature_1=50.0,
    radius_of_curvature_2=-50.0,
    thickness=5.0,
    diameter=25.0,
    material="BK7",
)

print(lens.calculate_focal_length())
print(lens.calculate_back_focal_length())
print(lens.calculate_working_flange_distance())
```

## Trace rays

```python
from openlens.ray_tracer import LensRayTracer

tracer = LensRayTracer(lens)
rays = tracer.trace_parallel_rays(num_rays=11)
```

## Analyze image quality

```python
from openlens.aberrations import AberrationsCalculator
from openlens.performance_metrics import PerformanceMetrics

aberrations = AberrationsCalculator(lens).calculate_all_aberrations(field_angle_deg=5.0)
report = PerformanceMetrics(lens).format_metrics_report()
```

Failed traces and undefined quantities return `None`; check before formatting.
For multi-element systems, use `OpticalSystem` from
`openlens.optical_system`. For persistence, use `DatabaseManager` or the GUI
`LensStorage` facade; JSON is an interchange format, not primary state.

## 📊 Quality Assessment System

### Automatic Quality Scoring (0-100)
The system analyzes aberrations and assigns a quality score:

**Excellent (90-100):**
- Spherical aberration < 0.001 mm
- Chromatic aberration < 0.1 mm
- Distortion < 1%
- Astigmatism < 0.1 mm

**Good (75-89):**
- Moderate aberrations
- Suitable for general optical applications

**Fair (60-74):**
- Noticeable aberrations
- May be acceptable for specific uses

**Poor (40-59):**
- Significant aberrations
- Design optimization recommended

**Very Poor (<40):**
- Severe aberrations
- Redesign necessary

### Issue Detection
Automatically identifies and reports:
- High spherical aberration
- Excessive chromatic aberration
- Significant distortion
- Problematic astigmatism

## 📚 Mathematical Foundations

### Formulas Implemented

1. **Spherical Aberration:**
   Exact trace (fallback: third-order Seidel):
   ```
   LSA = marginal focus - paraxial focus   (paraxial ray at y = 0.001 mm)
   LSA_Seidel = -(y²/8f)·[(n/(n-1))² + (n+2)/(n(n-1)²)·(B + 2(n²-1)/(n+2)·C)²]
   B = (c1+c2)/(c1-c2)  [shape factor from curvatures; flat c = 0], C = -1
   ```

2. **Coma:**
   ```
   Coma = (err_top + err_bottom) / 2   (traced tangential fan, chief-referenced)
   ```

3. **Astigmatism:**
   ```
   AST = |tan_focus - sag_focus|   (traced best-focus split, longitudinal)
   ```

4. **Field Curvature:**
   ```
   R_petzval = n · f
   ```

5. **Distortion:**
   ```
   Dist = 0  (single lens, stop at lens: S5 = 0 exactly)
   General stops: traced distortion curve (chief-ray heights)
   ```

6. **Chromatic Aberration:**
   ```
   LCA = f / V_d            (single thin lens)
   LCA = BFL_C - BFL_F      (systems: traced back focal lengths)
   V_d = Abbe number
   ```

7. **Airy Disk:**
   ```
   d_airy = 2.44 · λ · (f/D)
   ```

## 📝 Notes

### Known Limitations
1. **Single Lens Only:** Aberrations calculated for individual lenses, not systems
2. **Paraxial Approximation:** Uses third-order (Seidel) aberrations
3. **Monochromatic:** LCA calculated, but not full spectral analysis
4. **Simplified Formulas:** Professional tools use more complex ray tracing

### Design Decisions
- Used Seidel aberrations (industry standard for first-order analysis)
- Included Abbe number database for common materials
- Provided quality scoring for quick assessment
- Formatted output for readability

Features
--------

* **Interactive lens design** with spherical, conic, parabolic, and Fresnel
  surfaces, clear apertures, bevels, and coatings.
* **Multi-element assemblies** with air gaps, an aperture stop, element
  alignment, nesting, and undo/redo.
* **Ray tracing** in 2-D and 3-D, including point sources, off-axis fields,
  multiple wavelengths, ghosts, and total internal reflection.
* **Image quality** through Seidel aberrations, spot diagrams, PSF, MTF,
  wavefront error, Strehl ratio, and encircled energy.
* **Design tools** for optimization, tolerancing, thermal/environmental
  perturbations, and desensitization.
* **Mechanical and manufacturing** output: camera mounts, working flange
  distance, lens cells, spacers, STL/STEP solids, and ISO 10110-style drawings.
* **SQLite library** for lenses, assemblies, and tolerance sets, with JSON
  interchange and image/report export.
* **Material catalog** with Sellmeier dispersion, thermal expansion, and
  Schott TIE-19 temperature coefficients where available.
* **Optional dependencies** are guarded: the core model and ray tracer start
  without numpy, matplotlib, scipy, or Pillow.

## ===== docs/sphinx/source/user_guide.rst =====

GUI Overview
------------

The main window keeps one active target: either a single lens or an optical
assembly. Selecting a library row loads that target into the editor tabs.

Selection Tab
^^^^^^^^^^^^^

The **Selection** tab is the library browser. It supports:

- browsing and filtering lenses and assemblies;
- loading a row into the active-target tabs;
- creating, duplicating, renaming, and deleting library records;
- saving to the SQLite library;
- importing/exporting JSON for interchange.

The default library is a per-user SQLite database. The status bar reports save
and load failures; a failed save is never presented as a success.

Lens Editor Tab
^^^^^^^^^^^^^^^

The **Lens Editor** edits a single element and shows calculated properties as
the prescription changes.

**Surface parameters**

- Radius of curvature for each surface, in millimetres.
- Optional conic constant for each surface.
- Legacy parabolic sag control where a measured sag is preferred.
- Clear aperture and bevel for each surface.

**Geometry and material**

- Centre thickness and mechanical diameter.
- Material from the catalog, or a model glass defined by ``nd``/``Vd``.
- Design wavelength and operating temperature.
- Refractive index, either resolved from the selected glass or entered for a
  model glass.

**Coatings**

Each surface can carry a thin-film stack. Coating presets can be loaded from
the coating tools; the stack modulates reflected/transmitted energy while the
geometric ray direction continues to follow Snell's law.

**Calculated properties**

The panel updates focal length, optical power, back and front focal lengths,
working flange distance, edge thickness, and feasibility warnings. Thin or
negative edge thickness warnings mean the surfaces intersect inside the clear
aperture and the shape is not manufacturable as drawn.

Camera Mounts
^^^^^^^^^^^^^

The **Mount** group assigns a camera mount to the lens. It reports the
**working flange distance**, measured from the rear lens vertex to the sensor
plane:

.. code-block:: text

   working flange distance = back focal length + mount flange distance

Built-in mounts are C, CS, M42, M39, T, Fujifilm X, Leica M, Canon EF, and
Nikon F. Use **Manage mounts…** to add a custom mount from its flange
distance. Custom mounts are shared by every lens and stored in ``mounts.json``
under the per-user OpenLens data directory; ``OPENLENS_MOUNTS_PATH`` overrides
the file location.

.. code-block:: python

   from openlens.lens import Lens

   lens = Lens(radius_of_curvature_1=50.0, radius_of_curvature_2=-50.0)
   lens.mount_type = "M42"
   print(lens.calculate_working_flange_distance())

If the lens is afocal or the mount is unknown, the distance is ``None``. The
mount is saved with the lens in the SQLite library.

Assembly Tab
^^^^^^^^^^^^

The **Assembly** tab edits a multi-element ``OpticalSystem``:

- add, remove, reorder, and nest lens elements;
- set the air gap before each element;
- place an aperture stop in a gap and set its diameter;
- apply decenter and tilt to individual elements;
- inspect the optical layout and element positions;
- edit tolerances and alignment values for the assembly.

Assembly edits are undoable. The window-level undo/redo controls follow the
active lens editor or assembly stack.

Simulation Tab
^^^^^^^^^^^^^^

The **Simulation** tab traces rays through a lens or assembly:

- choose a parallel fan or point source;
- set ray count, field angle, and ray height range;
- trace at one or more wavelengths;
- enable ghost reflections to inspect unwanted paths;
- place the detector at an absolute image plane, or leave it on **Auto** for
  the paraxial focus. The view marks a configured plane and reports the RMS
  spot measured there in either mode; the Performance spot metric and the
  optimizer's RMS-spot target use the same plane;
- switch between 2-D and 3-D views;
- clear the trace and reset the view without changing the optical model.

Vignetted rays are dropped at clear apertures or the system stop. The status
area reports the trace result; a failed trace is not replaced by an empty
“perfect” image.

Performance Tab
^^^^^^^^^^^^^^^

The **Performance** tab calculates the image-quality dashboard:

- first-order values (EFL, BFL, f-number, numerical aperture);
- Seidel spherical, coma, astigmatism, field curvature, and distortion;
- axial and lateral chromatic estimates;
- RMS spot size and AIRY disk diameter;
- Strehl ratio and RMS wavefront error;
- MTF cutoff;
- spot diagram, ray fan, field curves, PSF, MTF, wavefront, and ghost views.

Expensive calculations run in background workers. If a trace or wavefront
sample fails, the affected field is reported as unavailable or invalid instead
of zero. See :doc:`scientific/image_quality` for the definitions and limits of
each metric.

Optimization Tab
^^^^^^^^^^^^^^^^

The **Optimization** tab builds a merit function from variables and targets:

- choose radii, thicknesses, air gaps, and selected system parameters as
  variables;
- target focal length, back focal length, aberration values, or other metrics;
- run the default simplex optimizer, or choose another available algorithm;
- inspect the merit value and variable values after convergence.

The merit function penalizes invalid geometry such as negative edge thickness.
Optimization runs on a copy of the model until the result is applied, so a
cancelled run does not leave a half-mutated assembly behind.

Tolerancing Tab
^^^^^^^^^^^^^^^

The **Tolerancing** tab studies manufacturing and environmental variation:

- define tolerance sets for radii, thickness, gaps, decentre, tilt, and index;
- run sensitivity or Monte Carlo analysis;
- inspect the distribution of spot, MTF, or other image-quality metrics;
- save tolerance sets with the lens or assembly metadata.

A nominal design with a small spot but no tolerance margin is not yet a
manufacturable design. Compensators and focus adjustment should be included
explicitly.

Startup and Updates
-------------------

The welcome screen checks the latest GitHub release in the background while the
rest of the window stays responsive. Under the title it reports one of:

- the running version is up to date;
- a newer version is available;
- the newer release has no build for the current operating system and
  architecture;
- the check could not reach GitHub.

The check is advisory. A network failure never blocks startup and never opens
an error dialog; use **Retry** on the welcome screen to check again.

When a compatible newer release exists, the available action depends on how
OpenLens was installed:

Standalone Linux and Windows build
    **Download and install** fetches the release asset, waits for the current
    process to exit, replaces the executable, and starts the new version. If
    the replacement cannot be written, the old executable is started again and
    the reason is written to ``openlens-update-error.log`` beside the
    downloaded file.

Standalone macOS build
    **Download and install** fetches the matching ``macOS-arm64`` or
    ``macOS-x64`` archive, extracts it under ``~/Downloads``, and opens the new
    application bundle. Drag that bundle to **Applications** to keep it, then
    close the old copy.

Source checkout or pip install
    **Download from GitHub** opens the release page. OpenLens does not replace
    a Python-managed installation behind the package manager's back.

After a standalone update restarts, the new version opens the SQLite library
normally. Schema migrations run as part of database initialization, so an
update that changes the schema upgrades the existing library in place. Back up
the database before skipping several major versions.

.. note::

   The update check contacts the public GitHub Releases API at startup. It
   sends no library data, only a request for the latest release metadata. Set
   ``OPENLENS_NO_UPDATE_CHECK=1`` to skip the request; the welcome screen then
   shows only the running version.

Ray Tracing
-----------

The UI ray tracer and the Python tracers share the same surface intersection
and refraction code. A parallel fan is launched relative to the front vertex;
the default fills the full aperture so rim aberration is included. Point
sources use a position and an angular range. Off-axis analysis rotates or
displaces the bundle instead of changing the lens model.

For a first-order check, use the paraxial matrix results (EFL, BFL, FFL).
For a real design, inspect the ray fans and spot diagrams at the intended
field and wavelength.

Mounts and Mechanical Output
----------------------------

**File → Export** provides:

- **STL** for lens solids and printable models;
- **STEP** for lenses plus suggested cells, spacers, and a barrel;
- **ISO 10110** for a manufacturing-style drawing;
- **Report** for a text/plot summary.

The STEP housing is derived from the current assembly and mount. Threads are
specified in the part name but are not modeled as helical solids without a CAD
kernel. Treat the suggested housing as a mechanical starting point and verify
it in CAD before manufacture.

Persistence and Interchange
---------------------------

SQLite is the application's source of truth. **Save** updates the active
library record; **Save As...** writes a JSON copy. JSON is also used for
import/export and for user preferences such as custom mounts, but it is not the
primary library.

A lens stores its mount type, wavelength, temperature, conic/parabolic terms,
clear apertures, bevels, coatings, and metadata. An assembly stores its element
order, air gaps, stop, alignment, and tolerance metadata. Round-tripping through
SQLite or JSON preserves those fields.

## ===== docs/sphinx/source/scientific/optics.rst =====

Optical Model
=============

This page collects the conventions and equations that OpenLens uses for
first-order layout, surface shape, and ray refraction. It is deliberately
close to the implementation so a calculated number can be reproduced by hand.

.. contents:: Table of Contents
   :local:
   :depth: 2

Sign Convention
---------------

OpenLens uses the usual Cartesian optical convention:

- Light propagates from left to right along the positive *x* axis.
- Surface vertices are the reference points for surface coordinates.
- A radius is positive when the centre of curvature lies to the right of the
  surface vertex. For a biconvex lens in air, ``R1 > 0`` and ``R2 < 0``.
- Distances to the right of a reference are positive.
- A converging element has positive effective focal length (EFL).
- Angles are measured from the optical axis; the ray tracer stores them in
  radians internally.

The Lens model uses the helium d-line, 587.6 nm, as its default design
wavelength and for ``nd``/``Vd`` catalog data. Visualization, spot diagrams,
PSF/MTF, and resolution defaults use the photopic green line, 550 nm.

Surface Shape
-------------

Spherical sag
^^^^^^^^^^^^^

For a spherical surface of radius ``R``, the vertex-referenced sag at radial
height ``r`` is

.. math::

   z(r) = \operatorname{sgn}(R)\left(|R| - \sqrt{R^2 - r^2}\right).

Flat surfaces have ``z = 0``. OpenLens clamps ``|r|`` to the real domain so a
ray outside the sphere's cap does not produce a complex sag.

Conic sag
^^^^^^^^^

A conic surface is described by the vertex radius ``R`` and conic constant
``K``:

.. math::

   z(r) = \frac{c r^2}{1 + \sqrt{1 - (1+K)c^2 r^2}},
   \qquad c = \frac{1}{R}.

The common special cases are:

- ``K = 0``: sphere.
- ``K = -1``: paraboloid.
- ``-1 < K < 0``: prolate ellipsoid.
- ``K > 0``: oblate ellipsoid.
- ``K < -1``: hyperboloid.

OpenLens also supports the older parabolic control, which stores the sag at
the half-diameter and scales it as ``z(r) = z_{D/2}(r/(D/2))^2``. The conic
model is preferred when an exact conic constant is known.

Lensmaker's Equation
--------------------

For a thick lens in air with refractive index ``n``, centre thickness ``d``
and surface radii ``R1`` and ``R2``:

.. math::

   \frac{1}{f} = (n-1)\left(
   \frac{1}{R1} - \frac{1}{R2}
   + \frac{(n-1)d}{n R1 R2}
   \right).

A flat surface contributes ``1/R = 0``. A plane-parallel plate therefore has
zero power, as expected. For a thin lens (``d`` small compared with the
radii), the last term is omitted.

Back and Front Focal Lengths
^^^^^^^^^^^^^^^^^^^^^^^^^^^^

The back focal length (BFL) is measured from the rear vertex to the rear
paraxial focus:

.. math::

   \mathrm{BFL} = f\left(1 - \frac{d P_1}{n}\right),
   \qquad P_1 = \frac{n-1}{R1}.

The front focal length (FFL) is a signed Cartesian coordinate measured from
the front vertex. For a converging lens the front focus lies to the left, so
the coordinate is negative:

.. math::

   \mathrm{FFL} = -f\left(1 - \frac{d P_2}{n}\right),
   \qquad P_2 = \frac{1-n}{R2}.

Both return ``None`` for an afocal element where the focal length is
undefined.

Camera Mounts and Working Flange
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

A camera mount fixes the sensor plane a specified flange distance behind the
mounting face. OpenLens models the mount as being at the lens rear vertex, so

.. math::

   \text{working flange distance} = \mathrm{BFL} + \text{mount flange distance}.

For example, a lens with a 27.93 mm BFL and an M42 mount (45.46 mm) has a
working flange distance of 73.39 mm. If the mount is unknown, or the lens is
afocal, the result is ``None`` rather than an assumed value.

Apertures, Bevels, and Stops
----------------------------

- The mechanical diameter is the outer lens diameter.
- A clear aperture, when set, is the polished optical aperture of that
  surface. Rays outside it are vignetted.
- Bevels model the protective chamfer at the rim and reduce the usable clear
  aperture near the edge.
- An optical system may define an aperture stop in an air gap. The stop has a
  diameter and is applied before the following element; rays outside it are
  blocked and reported as vignetted.
- Surface profiles are clamped to their real domain at the rim. A diameter
  larger than a spherical cap can support is therefore a validation issue, not
  a reason to invent a complex surface.

Ray Fans and Field Points
-------------------------

A parallel fan at angle ``θ`` is launched from a plane in front of the first
vertex. Its heights are chosen across a fraction of the semi-aperture; the
default is the full aperture so rim spherical aberration is included. Point
sources launch rays from a specified position with angles spanning a requested
range. Off-axis field analysis uses the same tracing machinery with a rotated
or displaced ray bundle.

## ===== docs/sphinx/source/scientific/image_quality.rst =====

Image Quality
=============

A lens prescription determines first-order properties, but two lenses with the
same focal length can form very different images. OpenLens reports both
geometric and diffraction-based measures. This page explains what each number
means and when it is trustworthy.

.. contents:: Table of Contents
   :local:
   :depth: 2

Seidel Aberrations
------------------

OpenLens reports the five primary (third-order) aberrations. Some are
calculator estimates from first-order parameters; field-dependent coma,
astigmatism, field curvature, and distortion use traced off-axis rays.

Spherical aberration
    Longitudinal shift between the paraxial focus and the marginal-ray focus.
    It is present on axis and grows rapidly with aperture. Stopping down
    reduces it.

Coma
    An off-axis aberration that makes a point source look like a comet.
    OpenLens estimates it from the asymmetry of the traced ray fan.

Astigmatism
    The tangential and sagittal ray fans focus at different distances. The
    reported value is the longitudinal separation of those foci.

Field curvature
    The image surface is curved rather than flat: best focus changes with
    field angle. A flat sensor therefore cannot be in focus everywhere.

Distortion
    The image height is not proportional to the ideal ``f tan θ`` mapping.
    Distortion moves points but does not by itself blur a point.

For a single spherical lens, third-order Seidel distortion is zero by
construction; the traced distortion curve is the useful measure.

Chromatic Aberration
--------------------

The refractive index depends on wavelength. OpenLens reports longitudinal
chromatic aberration as the focus shift between spectral lines. The Abbe
number is the usual first-order measure:

.. math::

   V_d = \frac{n_d - 1}{n_F - n_C}.

A low Abbe number means high dispersion and usually more chromatic
aberration. The calculation uses the material's catalog value where possible;
otherwise it falls back to a coarse estimate based on refractive index. Treat
that fallback as an estimate, not a measured glass property.

Achromatic Doublets
^^^^^^^^^^^^^^^^^^^

Combining a positive crown element with a negative flint element can bring two
wavelengths to a common focus. The cemented-doublet tools and optimizer in
OpenLens expose the element radii and glass choice as variables. A good
first-order achromat still needs a real ray check for spherical aberration and
manufacturing tolerances.

PSF
---

The point spread function is the image of an ideal point source. OpenLens can
compute it in two ways:

Geometric PSF
    Bin traced ray intersections on a detector grid. This is cheap and shows
    the geometric blur, but it ignores diffraction and can be noisy with few
    rays. The window grows to cover the traced spot; the result reports how
    much of the traced energy was captured. A low captured fraction means the
    PSF is clipped by the detector, not that the lens is perfect.

Diffraction PSF
    Take the complex pupil function from the traced wavefront and propagate it
    with an FFT. This includes diffraction and defocus, and is the appropriate
    model near the diffraction limit. It needs ``numpy`` and a sampled pupil.

The PSF is normalized so its integral represents the captured energy. When a
metric is computed from a clipped PSF, the report should be read together with
the captured fraction.

Strehl Ratio and Wavefront Error
--------------------------------

The Strehl ratio is the ratio of the aberrated peak irradiance to the ideal
peak. OpenLens obtains it from the traced pupil wavefront:

.. math::

   S = \left|\left\langle e^{i 2\pi W}\right\rangle\right|^2,

where ``W`` is the wavefront error in waves after piston and tilt are removed.
For small aberrations this is close to the Maréchal approximation

.. math::

   S \approx e^{-(2\pi\sigma)^2},

with ``σ`` the RMS wavefront error in waves. A Strehl ratio of 0.8 or above is
often treated as “diffraction limited”, but the threshold is a convention, not
a hard physical boundary.

Wavefront maps are sampled on a pupil grid. If too few rays reach the pupil,
the result is reported as unavailable rather than as a good wavefront.

Through-Focus and Tolerancing
-----------------------------

Image quality changes with focus. OpenLens can evaluate metrics at a requested
focus shift instead of assuming the paraxial image plane. A lens or assembly
can also pin an absolute detector plane with ``image_plane_x_mm``: spot-based
analyses, the RMS spot metric, and the optimizer's RMS-spot target then
measure at that plane. An unset plane keeps the paraxial focus as the default.
Tolerancing extends
this idea to manufacturing errors: element decentre, tilt, thickness, radius,
and index perturbations are sampled, and the resulting metric distribution is
reported. A nominal design with a good spot but no tolerance margin is not a
manufacturable design.

What the Numbers Do Not Cover
-----------------------------

- Geometric ray tracing ignores diffraction until the diffraction PSF/MTF
  branch is selected.
- Scalar diffraction does not model polarization or vector pupil effects;
  those need the coating/polarization models.
- A single-wavelength MTF does not describe a broadband image. Use the
  chromatic tools and multiple wavelengths.
- Ghost analysis follows unwanted reflections but does not predict sensor
  blooming or stray light outside the modeled aperture.
- Manufacturing tolerances are statistical inputs. The output is only as good
  as the distributions and compensators supplied.

Where to Look in the Code
-------------------------

- ``openlens/aberrations.py``: Seidel estimates, chromatic, Airy, Strehl.
- ``openlens/analysis/spot_diagram.py``: spot and encircled energy.
- ``openlens/analysis/geometric.py``: field curves and distortion.
- ``openlens/analysis/psf_mtf.py``: geometric and diffraction PSF/MTF.
- ``openlens/analysis/diffraction_psf.py``: pupil wavefront propagation.
- ``openlens/tolerancing.py``: Monte Carlo and sensitivity analysis.

## ===== docs/sphinx/source/scientific/thermal_mechanical.rst =====

Thermal Scaling
---------------

For a change in temperature ``ΔT`` from the 20 °C reference, a material with
linear coefficient of thermal expansion ``α`` changes its dimensions by

.. math::

   L(T) = L_0 \left(1 + \alpha \Delta T\right).

OpenLens applies this factor to the lens radii, centre thickness, diameter,
and - when a housing coefficient is supplied - to the air gaps. The radii and
thickness scaling preserves the shape of a homogeneous element to first order.
It is not a thermo-elastic finite-element model: it does not predict stress,
bending, or a cemented-interface failure.

The refractive index also changes. Catalog glasses can carry Schott TIE-19
coefficients ``D0``, ``D1``, ``D2``, ``E0``, ``E1`` and a thermal resonance
wavelength. When they are present, OpenLens evaluates

.. math::

   \Delta n = \frac{n^2-1}{2n}\left[
   D_0\Delta T + D_1\Delta T^2 + D_2\Delta T^3
   + \frac{E_0\Delta T + E_1\Delta T^2}{\lambda^2-\lambda_{tk}^2}
   \right],

with wavelength in micrometres. All-zero coefficients mean “no thermal data”,
and no correction is applied. A model glass defined only by ``nd``/``Vd`` has
no temperature coefficients either; its index is not invented.

Housing Expansion
-----------------

The air gaps are set by the mechanical housing, not by the glass. A first-order
estimate scales every gap by

.. math::

   g(T) = g_0 \left(1 + \alpha_\text{housing}\Delta T\right).

The default housing coefficient is aluminium, ``23.6 × 10⁻⁶ /K``. Steel is
roughly ``12 × 10⁻⁶ /K``, Invar ``1 × 10⁻⁶ /K``, and common plastics can be
tens to hundreds of ``10⁻⁶ /K``. Using the wrong housing coefficient can
change focus by more than the glass expansion does, especially in a long
assembly.

This is a uniform scaling model. A real barrel has a front and rear section,
retainers, and possibly different materials; those require a mechanical model
or a tolerance sensitivity study.

Where to Look in the Code
-------------------------

- ``openlens/analysis/environmental.py``: CTE, dn/dT, air index, conditioning.
- ``openlens/material_database.py``: thermal coefficients and glass data.
- ``openlens/mechanical_designer.py``: cells, spacers, barrel, mounts.
- ``openlens/mounts.py``: standard and custom flange distances.
- ``openlens/tolerancing.py``: perturbation, Monte Carlo, reports.
- ``openlens/io/step_export.py``: STEP solids for lenses and housings.

# openlens.global_optimizer.GlobalOptimizer.optimize_genetic
    def optimize_genetic(
        self,
        population_size: int = 50,
        generations: int = 50,
        mutation_rate: float = 0.1,
        crossover_rate: float = 0.7,
        callback: Optional[Callable[[int, float, List[float]], None]] = None,
    ) -> OptimizationResult:
        """
        Genetic Algorithm global optimization.
        Uses real-valued encoding.
        """

        # Initialize population
        population = []
        for _ in range(population_size):
            individual = []
            for var in self.variables:
                # Random value in range
                val = self._rng.uniform(var.min_value, var.max_value)
                individual.append(val)
            population.append(individual)

        # Add current design to population to ensure we don't regress
        current_design = [var.current_value for var in self.variables]
        population[0] = current_design

        best_overall_merit = float("inf")
        # Seeded with the starting design so it is never None. It used to
        # start as None and only be replaced when some design beat inf, so a
        # merit that never beat inf (NaN, or generations=0) left it None and
        # the elitism copy below raised TypeError.
        best_overall_design = list(current_design)
        best_overall_merit = self._evaluate_design(best_overall_design)
        # Captured separately: best_overall_merit is replaced whenever a
        # better design is found, so by the end it holds the best merit seen,
        # not the merit of the starting design.
        starting_merit = best_overall_merit

        history_merit = []

        for gen in range(generations):
            # Callback
            if callback and best_overall_design:
                callback(gen, best_overall_merit, best_overall_design)

            # Evaluate population
            merits = []
            for ind in population:
                # Also checked here, not just once per generation: the merit
                # can take seconds per evaluation, so a whole population of
                # 30 is over a minute during which the GUI's Stop does
                # nothing. The generation index is reported so the caller
                # still sees generation granularity.
                if callback and best_overall_design:
                    callback(gen, best_overall_merit, best_overall_design)
                m = self._evaluate_design(ind)
                merits.append(m)

            # Track best
            min_merit = min(merits)
            best_idx = merits.index(min_merit)

            # isfinite guards the comparison: NaN < x is False for every x, so
            # a NaN-scored generation would otherwise be skipped silently and
            # the elite kept unchanged.
            if math.isfinite(min_merit) and min_merit < best_overall_merit:
                best_overall_merit = min_merit
                best_overall_design = list(population[best_idx])

            history_merit.append(best_overall_merit)

            # Selection (Tournament)
            new_population = []

            # Elitism: Keep best
            new_population.append(list(best_overall_design))

            while len(new_population) < population_size:
                # Select two parents
                parent1 = self._tournament_select(population, merits)
                parent2 = self._tournament_select(population, merits)

                # Crossover
                if self._rng.random() < crossover_rate:
                    child = self._crossover(parent1, parent2)
                else:
                    child = list(parent1)

                # Mutation
                self._mutate(child, mutation_rate)

                new_population.append(child)

            population = new_population

        # Final refinement. As in the simulated-annealing path: the start is
        # passed explicitly rather than written into the caller's variable
        # objects, and the _apply_variables call was dead code.
        local_result = self.optimize_simplex(
            max_iterations=50, start=best_overall_design, callback=callback
        )

        # starting_merit is the merit of the design the search began from.
        # history_merit[0] would be the best of generation 0 - after up to 50
        # random mutations - and is empty entirely when generations=0, so
        # neither can serve as the baseline. iterations counts generations,
        # not the generations*population_size evaluations the old code
        # reported, and success comes from _finalize's bounds check rather
        # than a hardcoded True.
        return self._finalize(
            best_values=local_result.best_values,
            final_merit=local_result.final_merit,
            initial_merit=starting_merit,
            iterations=generations + local_result.iterations,
            variable_history=local_result.variable_history,
            merit_history=history_merit,
            converged_message=f"GA Completed {generations} generations",
            out_of_bounds_message=(
                f"GA finished {generations} generations outside variable bounds"
            ),
        )

# openlens.global_optimizer.GlobalOptimizer.optimize_simulated_annealing
    def optimize_simulated_annealing(
        self,
        max_iterations: int = 1000,
        initial_temperature: float = 100.0,
        cooling_rate: Optional[float] = None,
        restart_threshold: float = 1e-4,
        callback: Optional[Callable[[int, float, List[float]], None]] = None,
    ) -> OptimizationResult:
        """Simulated annealing global optimization.

        Args:
            max_iterations: Iterations to run. The default cooling schedule is
                derived from this, so the run lasts as long as asked for.
            initial_temperature: Starting temperature.
            cooling_rate: Geometric cooling factor. ``None`` (the default)
                derives one from ``max_iterations`` that reaches the annealing
                floor at exactly that many iterations. Pass a value to impose
                your own schedule; the run then ends when the temperature hits
                the floor, which may be well before ``max_iterations``.
            restart_threshold: Unused; retained for API compatibility.
            callback: Per-iteration progress callback. The GUI's cooperative
                cancel raises from here, so it is also consulted by the final
                local refinement.

        Returns:
            OptimizationResult with the best design found.
        """
        current_values = [var.current_value for var in self.variables]
        current_merit = self._evaluate_design(current_values)
        # Captured now because the annealing loop reassigns current_merit to
        # whichever neighbour it is currently sitting on.
        starting_merit = current_merit

        best_values = list(current_values)
        best_merit = current_merit

        variable_history = []
        merit_history = [current_merit]

        n_vars = len(self.variables)

        # temperature / initial_temperature is evaluated every iteration, so a
        # non-positive initial_temperature raised ZeroDivisionError on the very
        # first pass. Clamped rather than rejected: a zero *cooling* start is a
        # reasonable thing for a caller to mean.
        if initial_temperature <= 0:
            logger.warning(
                "initial_temperature=%r is not positive; clamping to a small "
                "positive value so annealing stays well defined.",
                initial_temperature,
            )
            initial_temperature = 1e-6

        # Initialise the loop variable *after* the clamp: assigning it first
        # copied the unclamped value, so a negative start made the first
        # iteration break on the temperature floor and no annealing ran.
        temperature = initial_temperature

        # The schedule has to fit inside max_iterations, or the run stops on
        # the temperature floor long before the caller asked it to. With the
        # defaults (T0 = 100, cooling 0.95) the floor at 1e-6 was reached at
        # ~360 iterations, so the GUI's max_iterations=500 was unreachable and
        # every annealing run silently stopped early.
        if cooling_rate is None:
            cooling_rate = self._derive_cooling_rate(initial_temperature, max_iterations)

        # max_iterations <= 0 leaves the loop body unentered, and `iteration` was
        # then read below for the iteration count - UnboundLocalError. -1 makes
        # that read yield 0 iterations.
        iteration = -1

        for iteration in range(max_iterations):
            # Callback
            if callback:
                callback(iteration, best_merit, best_values)

            # Create neighbor solution
            # Perturb one or more variables
            neighbor_values = list(current_values)

            # Adaptive perturbation based on temperature
            # At high T, larger jumps. At low T, smaller jumps.
            scale_factor = max(0.01, min(1.0, temperature / initial_temperature))

            # Select random variable to modify
            idx = self._rng.randint(0, n_vars - 1)
            var = self.variables[idx]

            # Random perturbation
            # Range is heuristic: step_size * scale * Gaussian
            delta = var.step_size * scale_factor * self._rng.gauss(0, 1)
            neighbor_values[idx] = var.clamp(neighbor_values[idx] + delta)

            # Evaluate neighbor
            neighbor_merit = self._evaluate_design(neighbor_values)

            # Acceptance probability
            delta_E = neighbor_merit - current_merit

            if delta_E < 0:
                # Better solution: always accept
                accept = True
            else:
                # Worse solution: accept with probability exp(-delta_E / T)
                # Avoid overflow
                if temperature < 1e-9:
                    prob = 0.0
                else:
                    prob = math.exp(-delta_E / temperature)

                accept = self._rng.random() < prob

            if accept:
                current_values = neighbor_values
                current_merit = neighbor_merit

                # Update best found so far
                if current_merit < best_merit:
                    best_merit = current_merit
                    best_values = list(current_values)

            # Cool down
            temperature *= cooling_rate

            # History
            variable_history.append(dict(zip([v.name for v in self.variables], current_values)))
            merit_history.append(current_merit)

            # Early stop if converged (optional, usually SA runs full course)
            if temperature < 1e-6:
                break

        # Final refinement: Run local simplex from the best point found.
        # The start is passed explicitly. It used to be transferred by writing
        # into self.variables[i].current_value - i.e. by mutating the caller's
        # OptimizationVariable objects, which the GUI also reads and saves, so
        # a simulated-annealing run silently overwrote the user's inputs. The
        # adjacent self._apply_variables(best_values) was dead code: it returns
        # a deepcopy and never mutates self.system.
        local_result = self.optimize_simplex(
            max_iterations=50, start=best_values, callback=callback
        )

        # Combine results. initial_merit is the *starting* design's merit:
        # merit_history[0] is the best of the first step, after a random
        # perturbation, so it understates the starting point and inflates
        # improvement. success comes from _finalize, which validates the bounds
        # instead of asserting True.
        return self._finalize(
            best_values=local_result.best_values,
            final_merit=local_result.final_merit,
            initial_merit=starting_merit,
            iterations=iteration + 1 + local_result.iterations,
            variable_history=variable_history + local_result.variable_history,
            merit_history=merit_history + local_result.merit_history,
            converged_message=(
                f"SA Converged after {iteration + 1} iterations"
                f" + {local_result.iterations} local steps"
            ),
            out_of_bounds_message=(
                f"SA finished after {iteration + 1} iterations"
                f" + {local_result.iterations} local steps outside variable bounds"
            ),
        )

# openlens.optimizer.LensOptimizer.optimize_simplex
    def optimize_simplex(
        self,
        max_iterations: int = 100,
        tolerance: float = 1e-6,
        callback: Optional[Callable[[int, float, List[float]], None]] = None,
        start: Optional[List[float]] = None,
    ) -> OptimizationResult:
        """
        Nelder-Mead simplex optimization
        Simple but robust algorithm for lens optimization

        Args:
            max_iterations: Iteration cap.
            tolerance: Merit spread below which the simplex is converged.
            callback: Optional per-iteration progress callback.
            start: Optional explicit starting point, one value per variable.
                GlobalOptimizer hands its best design here instead of writing
                the values into the caller's OptimizationVariable objects.
                Defaults to each variable's current_value.
        """
        n_vars = len(self.variables)

        if n_vars == 0:
            # With no variables the simplex has a single vertex, merit_range is
            # identically 0, and the loop "converges" on iteration 1 having
            # evaluated nothing and changed nothing - reported as success.
            raise ValueError(
                "optimize_simplex needs at least one variable; a design with "
                "nothing to optimise is not an optimisation problem"
            )
        if start is not None and len(start) != n_vars:
            raise ValueError(f"start has {len(start)} value(s) but there are {n_vars} variable(s)")

        # Initialize simplex (n+1 vertices in n-dimensional space)
        simplex = []
        current_values = (
            list(start) if start is not None else [var.current_value for var in self.variables]
        )

        # First vertex is the starting design
        simplex.append(current_values.copy())

        # Create n additional vertices by perturbing each variable.
        # Deliberately NOT clamped: out-of-bounds vertices earn a bound
        # penalty in _evaluate_design instead, so the search sees the true
        # landscape. Clamping collapses distinct vertices onto one bound
        # point, faking convergence (merit_range -> 0, success=True).
        for i in range(n_vars):
            vertex = current_values.copy()
            vertex[i] += self.variables[i].step_size
            simplex.append(vertex)

        # Evaluate merit for all vertices
        merit_values = [self._evaluate_design(vertex) for vertex in simplex]

        initial_merit = merit_values[0]
        variable_history = [dict(zip([v.name for v in self.variables], current_values))]
        merit_history = [initial_merit]

        # Simplex algorithm parameters
        alpha = 1.0  # Reflection
        gamma = 2.0  # Expansion
        rho = 0.5  # Contraction
        sigma = 0.5  # Shrinkage

        last_iteration = 0

        for iteration in range(max_iterations):
            last_iteration = iteration
            # Sort vertices by merit (best to worst)
            order = sorted(range(len(merit_values)), key=lambda i: merit_values[i])
            simplex = [simplex[i] for i in order]
            merit_values = [merit_values[i] for i in order]

            # Callback with best solution so far
            if callback:
                callback(iteration, merit_values[0], simplex[0])

            merit_range = merit_values[-1] - merit_values[0]
            n_clamped = sum(
                1
                for vertex in simplex
                if any(not var.is_valid(v) for var, v in zip(self.variables, vertex))
            )
            logger.debug(
                "simplex iter %d: merit_range=%.3g n_clamped=%d best=%.3g",
                iteration,
                merit_range,
                n_clamped,
                merit_values[0],
            )
            if n_clamped > n_vars / 2 and merit_range < tolerance:
                # Asphyxiation, not convergence: a majority of vertices is
                # pinned outside the box with no merit spread between them.
                return OptimizationResult(
                    success=False,
                    iterations=iteration + 1,
                    initial_merit=initial_merit,
                    final_merit=merit_values[0],
                    improvement=(
                        ((initial_merit - merit_values[0]) / initial_merit * 100)
                        if initial_merit > 0
                        else 0
                    ),
                    optimized_system=self._apply_variables(simplex[0]),
                    variable_history=variable_history,
                    merit_history=merit_history,
                    best_values=list(simplex[0]),
                    message=(
                        f"Aborted after {iteration + 1} iterations: {n_clamped} of "
                        f"{len(simplex)} simplex vertices stuck outside variable bounds"
                    ),
                )

            # Check convergence, relative to the merit's own magnitude.
            #
            # An absolute 1e-6 spread is meaningless on a merit carrying a
            # geometry penalty: at 1e8 the spacing between adjacent floats is
            # already ~1.5e-8, so merit_range can never fall below 1e-6 and the
            # run always burns the full iteration budget while the code is
            # written as though it had converged. Comparing against the merit
            # itself makes the test scale-blind.
            if self._merit_range_converged(merit_values, merit_range, tolerance):
                break

            # Calculate centroid of best n points (excluding worst)
            centroid = [sum(simplex[i][j] for i in range(n_vars)) / n_vars for j in range(n_vars)]

            # Reflection (unclamped: bounds are penalties, not walls)
            worst = simplex[-1]
            reflected = [centroid[j] + alpha * (centroid[j] - worst[j]) for j in range(n_vars)]
            reflected_merit = self._evaluate_design(reflected)

            if merit_values[0] <= reflected_merit < merit_values[-2]:
                # Accept reflection
                simplex[-1] = reflected
                merit_values[-1] = reflected_merit
            elif reflected_merit < merit_values[0]:
                # Try expansion
                expanded = [
                    centroid[j] + gamma * (reflected[j] - centroid[j]) for j in range(n_vars)
                ]
                expanded_merit = self._evaluate_design(expanded)

                if expanded_merit < reflected_merit:
                    simplex[-1] = expanded
                    merit_values[-1] = expanded_merit
                else:
                    simplex[-1] = reflected
                    merit_values[-1] = reflected_merit
            else:
                # Contraction
                contracted = [centroid[j] + rho * (worst[j] - centroid[j]) for j in range(n_vars)]
                contracted_merit = self._evaluate_design(contracted)

                if contracted_merit < merit_values[-1]:
                    simplex[-1] = contracted
                    merit_values[-1] = contracted_merit
                else:
                    # Shrink simplex toward best point
                    best = simplex[0]
                    for i in range(1, len(simplex)):
                        simplex[i] = [
                            best[j] + sigma * (simplex[i][j] - best[j]) for j in range(n_vars)
                        ]
                        merit_values[i] = self._evaluate_design(simplex[i])

            # Record history
            variable_history.append(dict(zip([v.name for v in self.variables], simplex[0])))
            merit_history.append(merit_values[0])

            last_iteration = iteration

        # Best solution (a best point outside the box is not a success,
        # even if the merit range converged: the design is unusable).
        best_values = simplex[0]
        final_merit = merit_values[0]

        return self._finalize(
            best_values=best_values,
            final_merit=final_merit,
            initial_merit=initial_merit,
            iterations=last_iteration + 1,
            variable_history=variable_history,
            merit_history=merit_history,
            converged_message=f"Converged after {last_iteration + 1} iterations",
            out_of_bounds_message=(
                f"Finished after {last_iteration + 1} iterations outside variable bounds"
            ),
        )

### openlens.global_optimizer.GlobalOptimizer.optimize_genetic

# Notes: `GlobalOptimizer.optimize_genetic` (openlens/global_optimizer.py)

## 1. Purpose
- A real-valued genetic algorithm over `self.variables`. It uses tournament selection, arithmetic crossover, Gaussian mutation and elitism.
- It then runs a local `optimize_simplex` from the best design and returns `self._finalize(...)`.

## 2. Inputs
- `population_size: int = 50`: number of individuals. Not validated.
- `generations: int = 50`: number of GA loops (`range(generations)`). Values ≤ 0 mean no loop.
- `mutation_rate: float = 0.1`: chance per gene of a Gaussian mutation (`rng.random() < rate`).
- `crossover_rate: float = 0.7`: chance per child of crossover (`rng.random() < crossover_rate`). Otherwise the child is a copy of parent1.
- `callback(gen, best_merit, best_design)`: optional. Also passed on to `optimize_simplex(callback=callback)`.
- Instance state used:
  - `self.variables`: list of `OptimizationVariable` with `current_value`, `min_value`, `max_value`, `clamp()`.
  - `self._rng = random.Random(seed)`, built in `__init__`.
- The following are inherited from `LensOptimizer` in `openlens/optimizer.py`, which is NOT shown, so their behaviour is unknown:
  - `self._evaluate_design(values)`
  - `self.optimize_simplex(max_iterations=50, start=..., callback=...)`
  - `self._finalize(**kw)`

## 3. Raises
- `population_size <= 0` raises `IndexError: list assignment index out of range`.
  - Cause: `population[0] = current_design` on an empty list.
  - This happens before any evaluation and even when `generations=0`.
  - Example: `opt.optimize_genetic(population_size=0)`.
- An exception raised inside `callback` propagates unchanged. This is the GUI's cancel mechanism.
  - Example: `callback=lambda *a: (_ for _ in ()).throw(RuntimeError("stop"))` raises `RuntimeError("stop")` on the first call.
  - The first call is `callback(0, start_merit, design)`, but only if `generations >= 1` and there is at least one variable.
- `_tournament_select`'s `ValueError("cannot select from an empty population")` cannot be reached through this method.
- Any error from `_evaluate_design`, `optimize_simplex` or `_finalize` comes from unseen code.

## 4. Returns / guarantees
Returns whatever `self._finalize(...)` returns, normally an `OptimizationResult`. It is called with exactly these keyword arguments:
- `best_values = local_result.best_values`
- `final_merit = local_result.final_merit`
- `initial_merit = starting_merit`
  - This is `_evaluate_design([v.current_value for v in variables])`, computed once before the loop.
- `iterations = generations + local_result.iterations`
  - This counts generations, not evaluations.
- `variable_history = local_result.variable_history`
  - Only the simplex history; the GA adds nothing.
- `merit_history = history_merit`
  - One entry per generation, so `len == max(generations, 0)`.
  - Each entry is the best-so-far merit, so the list is non-increasing.
  - It does NOT include the starting merit.
- `converged_message = f"GA Completed {generations} generations"`
- `out_of_bounds_message = f"GA finished {generations} generations outside variable bounds"`

How `_finalize` maps these to `success`, `message`, `improvement` and `optimized_system` is in the unseen module.

## 5. Side effects
- The `OptimizationVariable` objects are not mutated (`current_value` is unchanged). The source comment says this is deliberate.
- `self._rng` state advances.
- Whether `self.system` changes depends on the unseen `_evaluate_design` and `_finalize`. A comment says `_apply_variables` returns a deepcopy.

## 6. Branches and edge cases
**Initial population**
- `population_size` individuals, each with one `rng.uniform(min, max)` per variable.
- Individual 0 is then replaced by the current design. That design is not clamped, so it may lie outside the bounds.

**Each generation `gen`**
- The callback fires once at the start of the generation, then once before each individual's evaluation.
  - That is `1 + population_size` calls per generation, all with the same `gen`.
  - Condition: `callback and best_overall_design`. With zero variables the design is `[]` (falsy), so the callback is never called in the GA loop.
- The best design is updated only if `math.isfinite(min_merit) and min_merit < best_overall_merit`.
  - Ties keep the old design.
  - NaN or inf minima are ignored.
- The next population is built as follows:
  - Slot 0 is the elite: a copy of the best design.
  - Every other slot is a child of two tournament winners. Tournament size is `k = min(3, len(population))`, sampled without replacement, and the lowest merit wins.
- `population_size=1`: only the elite survives, so no selection or crossover happens.

**Crossover and mutation**
- Crossover gives `child[i] = a*p1[i] + (1-a)*p2[i]`, with one `a = rng.random()` per child. This is not clamped.
- Mutation adds `gauss(0, 0.1*(max-min))` to a gene and then clamps it with `var.clamp`.
  - With `min == max`, sigma is 0.

**Other cases**
- `generations=0`:
  - There is no GA loop and no GA callback.
  - `merit_history == []` and `iterations == 0 + local.iterations`.
  - The message is `"GA Completed 0 generations"`.
  - The simplex starts from the current design.
- The simplex `start` is the best design list. With 1 generation and a deterministic merit, it is a design whose merit is ≤ `starting_merit`, because the current design is in generation 0.

## 7. Rules from comments
- `best_overall_design` is seeded with the starting design, so it is never `None`. Elitism must not raise `TypeError` on NaN or on `generations=0`.
- `initial_merit` must be the starting design's merit, not `history_merit[0]`.
- `iterations` counts generations, not `generations * population_size`.
- `success` comes from `_finalize`'s bounds check, not a hard-coded `True`.

### openlens.global_optimizer.GlobalOptimizer.optimize_simulated_annealing

# Notes: `GlobalOptimizer.optimize_simulated_annealing`

## 1. Purpose
- Runs a seeded simulated-annealing search over `self.variables`.
- Then runs a local simplex refinement (`optimize_simplex(max_iterations=50, start=best_values, callback=callback)`) from the best point found.
- Returns the result built by `self._finalize(...)`.

**Not visible here:** `_evaluate_design`, `optimize_simplex`, `_finalize` and `OptimizationVariable.clamp` live in `openlens.optimizer`. Anything about merit values, `success`, and which message is chosen depends on that module.

## 2. Inputs
- **`max_iterations`** (int, default `1000`)
  - Upper bound on SA loop iterations (`range(max_iterations)`).
  - `<= 0` means the loop never runs.
- **`initial_temperature`** (float, default `100.0`)
  - If `<= 0`: logs a WARNING on logger `openlens.global_optimizer` (`"initial_temperature=%r is not positive; clamping ..."`) and sets it to `1e-6`.
  - It is not rejected.
- **`cooling_rate`** (float or None, default `None`)
  - `None` → `_derive_cooling_rate(T0, max_iterations)`:
    - returns `1.0` if `max_iterations <= 0`;
    - returns `1.0` if `ratio = 1e-6 / T0` is `>= 1.0` (i.e. `T0 <= 1e-6`);
    - otherwise returns `ratio ** (1/max_iterations)`.
  - An explicit value is used as-is, with no validation.
- **`restart_threshold`**: unused.
- **`callback(iteration, best_merit, best_values)`**
  - Called at the start of every SA iteration.
  - Also forwarded to `optimize_simplex`, so it is called more times after the SA loop.
  - Exceptions it raises propagate (this is how the GUI cancels).
- **Seed**: comes from `GlobalOptimizer(..., seed=...)` → private `random.Random(seed)`. The module-level `random` is never touched.

## 3. Raises
- **No explicit raises.**
- **Empty `variables` with `max_iterations >= 1`**: `self._rng.randint(0, -1)` raises `ValueError`.
  - The message varies by Python version, so assert the type only.
- **Exceptions from `callback`** propagate unchanged. For example, `def cb(*a): raise RuntimeError("stop")` → `pytest.raises(RuntimeError)`.

## 4. Returns / guarantees
- Returns an `OptimizationResult` from `_finalize`.
- **Arguments passed to `_finalize`** (n = number of SA iterations actually run, m = `local_result.iterations`):
  - `initial_merit` = `_evaluate_design([v.current_value for v in variables])`. This is the start design's merit, computed before any perturbation.
  - `iterations` = `n + m`.
  - `best_values` and `final_merit` are taken from the simplex result.
  - `variable_history` = SA history (n dicts `{var.name: value}` of the *current*, accepted point after each step) + simplex history.
  - `merit_history` = `[starting_merit]` + n current merits + simplex `merit_history`.
- **Messages:**
  - Converged: `f"SA Converged after {n} iterations + {m} local steps"`.
  - Out of bounds: `f"SA finished after {n} iterations + {m} local steps outside variable bounds"`.
  - Which one is used, and `success`, is decided by `_finalize` (unseen). The likely rule is the converged message when inside the bounds; verify loosely with `startswith("SA ")` or `"iterations + " in msg`.
- **Value of n:**
  - Derived rate and T0 > 1e-6: n == `max_iterations` (the floor is reached at the last step).
  - `max_iterations <= 0`: n = 0, because `iteration` starts at -1. SA `variable_history` is empty and the SA part of `merit_history` is `[starting_merit]`.
  - Explicit rate: the loop breaks after the cooling step once `temperature < 1e-6`. Example: `initial_temperature=1.0, cooling_rate=0.5, max_iterations=100` → n = 20 (2^-20 ≈ 9.5e-7; 2^-19 ≈ 1.9e-6).
  - `cooling_rate >= 1` with T0 > 1e-6: never cools, so n = `max_iterations`.

## 5. Side effects
- Does **not** write to `var.current_value` of the caller's `OptimizationVariable` objects (the comment says this explicitly).
- Consumes the instance's private RNG, so a second call on the same instance draws different numbers.
- Logs a warning only for `initial_temperature <= 0`.
- Mutation of `self.system` by simplex/_finalize is not visible here; the comment says `_apply_variables` returns a deepcopy.

## 6. Branches / edge cases
- **Each step:**
  - Picks one random index, `delta = step_size * clamp(T/T0, 0.01, 1.0) * gauss(0,1)`.
  - The neighbour value is `var.clamp(old + delta)`.
  - Only ONE variable changes per step.
- **Acceptance:**
  - `delta_E < 0` → accept.
  - Otherwise, if `T < 1e-9` → prob 0.
  - Otherwise prob = `exp(-delta_E/T)`, accepted if `rng.random() < prob`.
  - The best point is updated only on strict improvement.
- **`initial_temperature <= 0`** (e.g. `-5` or `0`):
  - Clamped to `1e-6`; the derived rate is `1.0`.
  - Temperature stays at `1e-6`, which is not `< 1e-6`, so the run lasts the full `max_iterations` and a warning is logged.
- **`0 < initial_temperature < 1e-6`** (e.g. `1e-12`), not clamped:
  - Derived rate is `1.0`, and the temperature is already below the floor.
  - Breaks after exactly **1** SA iteration.
  - Since `T < 1e-9`, worse neighbours are never accepted.
- **`max_iterations=0`**: SA is skipped; the simplex still runs from the start values.

## 7. Rules from comments
- `seed=` must make runs reproducible, using a private generator.
- The default schedule must last exactly `max_iterations`.
- `initial_merit` is the starting design's merit, not `merit_history[0]` after a perturbation.
- Caller variables must not be mutated.
- The callback is also consulted during the final refinement.

## 8. Testing hints
- **Building inputs:**
  - Build a system with `sys = OpticalSystem(); sys.add_lens(Lens())`.
  - Build variables like `OptimizationVariable("r1", 0, "radius_of_curvature_1", 50.0, 20.0, 200.0, step_size=5.0)`.
  - Use a target like `OptimizationTarget("focal_length", 100.0)`.
  - Valid parameter and target names are defined in `openlens.optimizer` (unseen). Use the obvious ones above and avoid asserting merit values.
- **Speed:** keep `max_iterations` small (5–30), since the simplex adds up to 50 iterations.
- **Robust assertions:**
  - Same seed with two freshly built optimizers gives equal `best_values`, `final_merit` and `merit_history`.
  - `result.initial_merit == GlobalOptimizer(...)._evaluate_design([v.current_value for v in vars])`, or equivalently equals `merit_history[0]`.
  - `variables[i].current_value` is unchanged after the run.
  - Record callback args; the first call is `(0, initial_merit, start_values)`.
  - Count the calls whose first arg comes from the SA phase: `callback` is called at least n times, and the first n calls have iteration = 0..n-1 in order.
  - `max_iterations=0` → `"after 0 iterations"` appears in the message.
  - Explicit `T0=1.0, rate=0.5` → message contains `"after 20 iterations"`.
  - `T0=1e-12` → `"after 1 iterations"`.
  - With the derived rate and `max_iterations=10` → `"after 10 iterations"`.
  - `T0=-1` emits a WARNING (`caplog`) and runs the full `max_iterations`.
  - SA part of `variable_history`: the first n entries have keys = variable names, all values within [min, max], and consecutive entries differ in at most one key.
- **Pitfalls:**
  - `best_values` passed to the callback may be the same list object later rebound; copy it when recording.
  - Do not assert the exact `success` value or the exact simplex iteration count; both come from unseen code.
  - The total `iterations` field is `>= n`, not `== n`.

### openlens.optimizer.LensOptimizer.optimize_simplex

# Notes: `LensOptimizer.optimize_simplex(max_iterations=100, tolerance=1e-6, callback=None, start=None)`

## 1. Purpose
- Runs a Nelder–Mead simplex search over `self.variables` to minimise `self._evaluate_design(values)`.
- Returns an `OptimizationResult`.
- `optimize(max_iterations, tolerance, callback)` simply calls `optimize_simplex(max_iterations, tolerance, callback)`.

## 2. Inputs
- **`max_iterations`** (int): upper bound for `for iteration in range(max_iterations)`. A value of `0` means the loop never runs.
- **`tolerance`** (float): a *relative* convergence bound. The loop converges when either:
  - `merit_range <= 0.0`, or
  - `merit_range <= max(tolerance * max(|m| for m in merit_values), 1e-12)`.
- **`callback(iteration, best_merit, best_values_list)`**:
  - Called once at the top of every loop iteration, after sorting.
  - The arguments are the 0-based iteration index, `merit_values[0]` and `simplex[0]`.
  - It is called even on the iteration that then converges or aborts.
- **`start`**: an optional sequence with one value per variable. It is copied with `list(start)`.
  - If omitted, the start is `[v.current_value for v in self.variables]`.
  - The variables' `current_value` is never written.
- Initial simplex:
  - Vertex 0 is the start.
  - Vertex `i+1` is the start with `values[i] += variables[i].step_size`.
  - The vertices are **not clamped** to bounds.
  - Exactly `n_vars + 1` calls to `_evaluate_design` happen before the loop.
- How `_evaluate_design(values)` scores a point:
  - It returns `merit_function.evaluate(self._apply_variables(values)) + bound_penalty`.
  - `bound_penalty = Σ 1e6 * (v - clamp(v))**2` over out-of-bounds variables.
  - Results are cached on `tuple(round(v, 10))`, a FIFO cache capped at 4096 entries.
  - A NaN merit is replaced by `INFEASIBLE_MERIT = 1e9`.

## 3. Raises
Both checks run before any evaluation, in this order:
1. **No variables.** `ValueError("optimize_simplex needs at least one variable; a design with nothing to optimise is not an optimisation problem")`.
   - Trigger: `LensOptimizer(OpticalSystem(), [], []).optimize_simplex()`.
2. **Wrong `start` length.** `ValueError(f"start has {len(start)} value(s) but there are {n_vars} variable(s)")`.
   - Example: 1 variable with `start=[1.0, 2.0]` gives `"start has 2 value(s) but there are 1 variable(s)"`.
   - `start=[]` with 1 variable also raises, because `[]` is not `None`.
- An empty variable list with a bad `start` raises error 1, not error 2.
- `optimize()` raises the same errors.

## 4. Returns: `OptimizationResult`
- **`initial_merit`**: the merit of the start vertex.
- **`variable_history`**:
  - Starts as `[{var.name: start_value, ...}]`.
  - One dict is appended per iteration that neither converged nor aborted.
- **`merit_history`**:
  - Starts as `[initial_merit]` and is appended in step with `variable_history`, so the two always have the same length.
  - It is the best-so-far value, so it is non-increasing.
- **`iterations`**: `last_iteration + 1`.
  - Equals `1` when `max_iterations=0`.
  - Equals `k+1` if the loop breaks at iteration `k`.
  - Equals `max_iterations` if the loop runs to the end.
- **Normal exit**, via `_finalize`:
  - `best_values = list(simplex[0])` and `final_merit = merit_values[0]`.
  - `optimized_system = self._apply_variables(best_values)`, a deep copy; `self.system` is untouched.
  - `best_valid` is true when every variable satisfies `min <= v <= max`.
  - `feasible` is `not merit_function.has_hard_violation(optimized_system)`, i.e. the physical penalty is below `1e8`.
  - `success = best_valid and feasible`.
  - Message:
    - success: `f"Converged after {N} iterations"`. This is printed even when the iteration budget ran out without converging.
    - out of bounds: `f"Finished after {N} iterations outside variable bounds"`.
    - in bounds but a hard violation: `"Converged, but the design breaks a physical constraint (it cannot be made as it is)"`.
- **`improvement`**: `(initial - final) / initial * 100` if `initial_merit > 0`, else the int `0`.
- **Abort exit ("asphyxiation")**:
  - Checked inside the loop, before the convergence test.
  - Condition: `n_clamped > n_vars/2 and merit_range < tolerance`, where `n_clamped` counts vertices with any variable out of bounds.
  - Result: `success=False`, `iterations=iteration+1`, `best_values=list(simplex[0])`.
  - Message: `f"Aborted after {iteration+1} iterations: {n_clamped} of {n_vars+1} simplex vertices stuck outside variable bounds"`.
  - `has_hard_violation` is not checked on this path.

## 5. Side effects
- Does not mutate `self.system`, `self.variables` or the `start` list.
- Fills `self._merit_cache`.
- Sorting by merit is stable, so tied vertices keep their order: the start vertex stays `simplex[0]` when tied.

## 6. Branches with concrete inputs
Fixture for all cases:
- `sys = OpticalSystem()` (empty, so no physical penalty: no elements and no gaps).
- `targets=[]`, so `merit_function.evaluate` is `0.0` and the merit equals the bound penalty.
- `parameter="dummy"`: unknown names are a no-op in `_apply_single_variable`.

```python
v = OptimizationVariable("x", 0, "dummy", 5.0, 0.0, 10.0, step_size=1.0)
opt = LensOptimizer(OpticalSystem(), [v], [])
```

- **Converge at iteration 0**: `opt.optimize_simplex()`.
  - Both vertices (5, 6) have merit 0, so the range is 0.
  - Result: `success True`, `iterations 1`, `best_values [5.0]`, `final_merit 0.0`, `improvement 0`.
  - Message: `"Converged after 1 iterations"`.
  - History lengths are 1. The callback is called exactly once, with `(0, 0.0, [5.0])`.
- **`max_iterations=0`, in bounds**:
  - Same values as above, but the callback is never called.
  - `_evaluate_design` is called exactly twice, with `[5.0]` then `[6.0]`.
- **`max_iterations=0`, `start=[5.0]`, bounds [0, 1]**:
  - `initial_merit = final_merit = 1e6*16 = 1.6e7`, `improvement 0.0`.
  - `success False`, message `"Finished after 1 iterations outside variable bounds"`, `best_values [5.0]`.
- **Abort**: the same out-of-bounds variable with `opt._evaluate_design = lambda vals: 0.0` (instance override).
  - Vertices 5 and 6 are both out of bounds, and the range 0 is `< 1e-6`.
  - Result: `success False`, `iterations 1`, `best_values [5.0]`.
  - Message: `"Aborted after 1 iterations: 2 of 2 simplex vertices stuck outside variable bounds"`.
- **Real search**:
  - Setup: `opt._evaluate_design = lambda vals: (vals[0]-3.0)**2`, bounds [-100, 100], start 0, `max_iterations=200`.
  - Expect `best_values[0] ≈ 3` (abs tolerance 1e-3), `success True` and `final_merit <= initial_merit (=9.0)`.
  - `merit_history` is non-increasing.
- **Budget exhausted**: the quadratic above with `max_iterations=2`.
  - Expect `iterations == 2` and `len(merit_history) == 3`, provided it does not converge within 2 iterations.

## 7. Rules from comments
- Bounds act as penalties, not walls; nothing is clamped during the search.
- A best point outside the box is never reported as a success.
- A hard physical violation is never reported as a success.
- `start` exists so that GlobalOptimizer does not need to write into the caller's variables.

## 8. Testing hints / pitfalls
- Prefer the empty `OpticalSystem()` plus `"dummy"` parameter setup. Real lens targets go through ray tracing and aberration code (other modules), whose numbers you cannot predict.
- Overriding `opt._evaluate_design` on the instance works because the method calls `self._evaluate_design`. `_finalize` still uses the real `_apply_variables` and `has_hard_violation`, which is fine with an empty system.
- Do not assert exact iteration counts or vertex sequences for a real search; assert bounds or approximate optima instead.
- The int `0` compares equal to `0.0`, so `improvement == 0` is safe.
- After the call, assert that `v.current_value` is unchanged and that `result.optimized_system is not opt.system`.

### openlens.optimizer.OptimizationResult

# Notes: `openlens.optimizer.OptimizationResult`

## 1. Purpose
- A plain `@dataclass` that holds the outcome of an optimizer run.
- It has no methods of its own. Everything it offers is auto-generated by `dataclass`: `__init__`, `__repr__` and `__eq__`.
- The optimizers (`optimize_simplex`, `optimize`, `optimize_gradient_descent`, and the global optimizers via `_finalize`) build and return it.

## 2. Inputs (constructor fields, in this exact positional order)
| # | field | type hint | default |
|---|---|---|---|
| 1 | `success` | bool | required |
| 2 | `iterations` | int | required |
| 3 | `initial_merit` | float | required |
| 4 | `final_merit` | float | required |
| 5 | `improvement` | float | required |
| 6 | `optimized_system` | OpticalSystem | required |
| 7 | `variable_history` | List[Dict[str,float]] | `field(default_factory=list)` → new `[]` |
| 8 | `merit_history` | List[float] | `field(default_factory=list)` → new `[]` |
| 9 | `message` | str | `""` |
| 10 | `best_values` | List[float] | `field(default_factory=list)` → new `[]` |

- There is no validation, type checking or normalisation. Any value is stored exactly as given, the same object, not copied.
- For example, `OptimizationResult("x", "y", None, None, None, None)` is accepted.
- The dataclass is not frozen, so fields can be reassigned after construction.

## 3. Raises
- `TypeError` (from the dataclass `__init__`) when any of the 6 required fields is missing.
  - Example: `OptimizationResult(True, 1, 1.0, 0.5, 50.0)` raises `TypeError`, because `optimized_system` is missing.
- `TypeError` for an unknown keyword argument, e.g. `foo=1`.
- `TypeError` for more than 10 positional arguments.

Errors raised by the producers, before any result exists:
- `optimize_simplex` with zero variables raises `ValueError`:
  `"optimize_simplex needs at least one variable; a design with nothing to optimise is not an optimisation problem"`
- `optimize_simplex(start=[...])` with a wrong length raises `ValueError`:
  `f"start has {len(start)} value(s) but there are {n_vars} variable(s)"`
- An unknown target name raises `ValueError` from `MeritFunction.evaluate` on the first evaluation:
  `f"Unknown optimization target {name!r}; known targets: chromatic_aberration, coma, astigmatism, ..."`
  - The list of known targets is sorted alphabetically and joined with `", "`.
  - Sorted order: `astigmatism, chromatic_aberration, coma, focal_length, mtf, rms_spot_radius, spherical_aberration, system_length`.

## 4. Returns and guarantees
- Each instance gets its own fresh list for each of `variable_history`, `merit_history` and `best_values`. Two default-constructed instances never share a list.
- `__eq__` compares all 10 fields in order, and only against another `OptimizationResult`. Comparing with a tuple or dict gives `False`.
  - Equality of `optimized_system` depends on `OpticalSystem.__eq__`, which is defined in another module and not visible here (probably identity).
  - In equality tests, pass the same system object (or `None`) to both instances.
- `__repr__` has the form `OptimizationResult(success=True, iterations=3, ..., best_values=[])`, with fields in the order above.
- The class is not hashable as a set member: a dataclass with `eq=True` and not frozen has `__hash__ = None`.

How the producers fill the fields:
- **`_finalize`** (used by simplex and the global optimizers):
  - `best_values=list(best_values)` is a new list.
  - `improvement = (initial-final)/initial*100` when `initial_merit > 0`, else `0` (an int).
  - `success` is true only if every best value satisfies `var.is_valid` and there is no hard physical violation.
  - `message` is one of:
    - on success: `f"Converged after {N} iterations"`
    - when out of bounds: `f"Finished after {N} iterations outside variable bounds"`
    - when there is a hard violation: `"Converged, but the design breaks a physical constraint (it cannot be made as it is)"`
- **Simplex abort path**: `success=False`, with the message `f"Aborted after {k} iterations: {n_clamped} of {n+1} simplex vertices stuck outside variable bounds"`.
- **Simplex history**:
  - `variable_history[0]` is `{var.name: start_value}`.
  - `merit_history[0]` equals `initial_merit`.
  - `len(merit_history) == len(variable_history)`.
- **`optimize_gradient_descent`**:
  - It does not pass `best_values`, so `best_values == []`.
  - `success` is the final in-bounds check only.
  - `message` is `f"Completed {N} iterations"`, or `f"Finished {N} iterations outside variable bounds"` when out of bounds.
  - `merit_history` is non-increasing, and `final_merit == merit_history[-1]`.
- `iterations` is always ≥ 1 when produced by an optimizer.

## 5. Side effects
- None. Construction does not copy or mutate its arguments.
- Mutating a list passed in also mutates the field, because the field is the same object.

## 6. Branches and edge cases
- Explicit lists: with `vh = [{"a": 1.0}]`, constructing with `variable_history=vh` gives `r.variable_history is vh`.
- Independent defaults: `r1.merit_history.append(1.0)` leaves `r2.merit_history == []`.
- `message` defaults to an empty string: `r.message == ""`.

## 7. Rules from comments
- `best_values` is "the design the search settled on". Global optimizers refine with a second pass and report the values they actually return.
- A best point outside the variable box is never `success`, even if the merit converged.

## 8. Testing hints
- Pass `None` or any sentinel `object()` as `optimized_system` for pure dataclass tests. No `OpticalSystem` is needed.
- Use `dataclasses.fields(OptimizationResult)` to pin the names and order: `[f.name for f in fields(...)]` equals the 10 names above.
- Pin the defaults with `fields(...)[8].default == ""`. For list fields, `f.default_factory is list`.
- Use `dataclasses.asdict(r)` only when `optimized_system` is something simple such as `None`. `asdict` deep-copies nested values.
- Do not assert `hash(r)`; it raises `TypeError`.
- For results produced by an optimizer:
  - Assert structural facts: types, `merit_history[0] == initial_merit`, the message prefix, and `best_values` being a `list` distinct from internal state.
  - Do not assert exact merit numbers. They depend on ray tracing and lens code in other modules.
- `improvement` is the int `0` (not `0.0`) when `initial_merit <= 0`. Compare it with `==`, not with `is`.

Write pytest tests for these functions: openlens.global_optimizer.GlobalOptimizer.optimize_genetic, openlens.global_optimizer.GlobalOptimizer.optimize_simulated_annealing, openlens.optimizer.LensOptimizer.optimize_simplex, openlens.optimizer.OptimizationResult.
Test the documented behavior, including edge cases the documentation implies.
Use only the public API and pandas/numpy. Keep it to at most 15 focused tests.
