# Notes: `openlens.optimizer.OptimizationResult`

## 1. Purpose
- A plain `@dataclass` that holds the outcome of an optimizer run.
- It has no methods of its own. Everything it offers is auto-generated by `dataclass`: `__init__`, `__repr__` and `__eq__`.
- The optimizers (`optimize_simplex`, `optimize`, `optimize_gradient_descent`, and the global optimizers via `_finalize`) build and return it.

## 2. Inputs (constructor fields, in this exact positional order)
| # | field | type hint | default |
|---|---|---|---|
| 1 | `success` | bool | required |
| 2 | `iterations` | int | required |
| 3 | `initial_merit` | float | required |
| 4 | `final_merit` | float | required |
| 5 | `improvement` | float | required |
| 6 | `optimized_system` | OpticalSystem | required |
| 7 | `variable_history` | List[Dict[str,float]] | `field(default_factory=list)` → new `[]` |
| 8 | `merit_history` | List[float] | `field(default_factory=list)` → new `[]` |
| 9 | `message` | str | `""` |
| 10 | `best_values` | List[float] | `field(default_factory=list)` → new `[]` |

- There is no validation, type checking or normalisation. Any value is stored exactly as given, the same object, not copied.
- For example, `OptimizationResult("x", "y", None, None, None, None)` is accepted.
- The dataclass is not frozen, so fields can be reassigned after construction.

## 3. Raises
- `TypeError` (from the dataclass `__init__`) when any of the 6 required fields is missing.
  - Example: `OptimizationResult(True, 1, 1.0, 0.5, 50.0)` raises `TypeError`, because `optimized_system` is missing.
- `TypeError` for an unknown keyword argument, e.g. `foo=1`.
- `TypeError` for more than 10 positional arguments.

Errors raised by the producers, before any result exists:
- `optimize_simplex` with zero variables raises `ValueError`:
  `"optimize_simplex needs at least one variable; a design with nothing to optimise is not an optimisation problem"`
- `optimize_simplex(start=[...])` with a wrong length raises `ValueError`:
  `f"start has {len(start)} value(s) but there are {n_vars} variable(s)"`
- An unknown target name raises `ValueError` from `MeritFunction.evaluate` on the first evaluation:
  `f"Unknown optimization target {name!r}; known targets: chromatic_aberration, coma, astigmatism, ..."`
  - The list of known targets is sorted alphabetically and joined with `", "`.
  - Sorted order: `astigmatism, chromatic_aberration, coma, focal_length, mtf, rms_spot_radius, spherical_aberration, system_length`.

## 4. Returns and guarantees
- Each instance gets its own fresh list for each of `variable_history`, `merit_history` and `best_values`. Two default-constructed instances never share a list.
- `__eq__` compares all 10 fields in order, and only against another `OptimizationResult`. Comparing with a tuple or dict gives `False`.
  - Equality of `optimized_system` depends on `OpticalSystem.__eq__`, which is defined in another module and not visible here (probably identity).
  - In equality tests, pass the same system object (or `None`) to both instances.
- `__repr__` has the form `OptimizationResult(success=True, iterations=3, ..., best_values=[])`, with fields in the order above.
- The class is not hashable as a set member: a dataclass with `eq=True` and not frozen has `__hash__ = None`.

How the producers fill the fields:
- **`_finalize`** (used by simplex and the global optimizers):
  - `best_values=list(best_values)` is a new list.
  - `improvement = (initial-final)/initial*100` when `initial_merit > 0`, else `0` (an int).
  - `success` is true only if every best value satisfies `var.is_valid` and there is no hard physical violation.
  - `message` is one of:
    - on success: `f"Converged after {N} iterations"`
    - when out of bounds: `f"Finished after {N} iterations outside variable bounds"`
    - when there is a hard violation: `"Converged, but the design breaks a physical constraint (it cannot be made as it is)"`
- **Simplex abort path**: `success=False`, with the message `f"Aborted after {k} iterations: {n_clamped} of {n+1} simplex vertices stuck outside variable bounds"`.
- **Simplex history**:
  - `variable_history[0]` is `{var.name: start_value}`.
  - `merit_history[0]` equals `initial_merit`.
  - `len(merit_history) == len(variable_history)`.
- **`optimize_gradient_descent`**:
  - It does not pass `best_values`, so `best_values == []`.
  - `success` is the final in-bounds check only.
  - `message` is `f"Completed {N} iterations"`, or `f"Finished {N} iterations outside variable bounds"` when out of bounds.
  - `merit_history` is non-increasing, and `final_merit == merit_history[-1]`.
- `iterations` is always ≥ 1 when produced by an optimizer.

## 5. Side effects
- None. Construction does not copy or mutate its arguments.
- Mutating a list passed in also mutates the field, because the field is the same object.

## 6. Branches and edge cases
- Explicit lists: with `vh = [{"a": 1.0}]`, constructing with `variable_history=vh` gives `r.variable_history is vh`.
- Independent defaults: `r1.merit_history.append(1.0)` leaves `r2.merit_history == []`.
- `message` defaults to an empty string: `r.message == ""`.

## 7. Rules from comments
- `best_values` is "the design the search settled on". Global optimizers refine with a second pass and report the values they actually return.
- A best point outside the variable box is never `success`, even if the merit converged.

## 8. Testing hints
- Pass `None` or any sentinel `object()` as `optimized_system` for pure dataclass tests. No `OpticalSystem` is needed.
- Use `dataclasses.fields(OptimizationResult)` to pin the names and order: `[f.name for f in fields(...)]` equals the 10 names above.
- Pin the defaults with `fields(...)[8].default == ""`. For list fields, `f.default_factory is list`.
- Use `dataclasses.asdict(r)` only when `optimized_system` is something simple such as `None`. `asdict` deep-copies nested values.
- Do not assert `hash(r)`; it raises `TypeError`.
- For results produced by an optimizer:
  - Assert structural facts: types, `merit_history[0] == initial_merit`, the message prefix, and `best_values` being a `list` distinct from internal state.
  - Do not assert exact merit numbers. They depend on ray tracing and lens code in other modules.
- `improvement` is the int `0` (not `0.0`) when `initial_merit <= 0`. Compare it with `==`, not with `is`.
