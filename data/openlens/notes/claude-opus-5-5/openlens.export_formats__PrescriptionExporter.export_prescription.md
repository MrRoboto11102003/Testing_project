# Notes: `PrescriptionExporter.export_prescription(lens, filename)`

## 1. Purpose
- Writes a plain-text "lens prescription" for one `Lens` to `filename`.
- Returns nothing. Callers observe it only through the file it writes.

## 2. Inputs
- `lens`: a `openlens.Lens`, or any object with these attributes:
  - `name`, `lens_type`, `radius_of_curvature_1`, `radius_of_curvature_2`
  - `thickness`, `diameter`, `material`, `refractive_index`
  - a `calculate_focal_length()` method
- `filename`: a path (str; `atomic_write_text(path: Any)` also accepts a `Path`). The function does no validation of its own.
- The file is written through `atomic_write_text(filename)` with default `encoding='utf-8'` and `newline=None`. Its contents replace `path` only if the `with` block succeeds. Its internals are in `openlens.atomic`, which is not shown.

## 3. Raises
- The function raises nothing explicitly.
- Errors from `atomic_write_text` propagate, for example a non-existent parent directory. The exact exception type comes from `openlens.atomic` (not shown), so assert only with `pytest.raises(Exception)`, if at all.
- An attribute missing on `lens` raises `AttributeError`.
- If any formatted value is `None` (e.g. `refractive_index`), the `:.3f`/`:.4f` format raises `TypeError`. A real `Lens` presumably always has numbers here.
- If the block fails, the file is not replaced. The previous content is kept, or no file appears.

## 4. Returns and guarantees
- Returns `None`.
- The file content is exactly this, with `\n` line endings in the written text:
```
LENS PRESCRIPTION
============================================================      <- "=" * 60

Lens Name: {lens.name}
Lens Type: {lens.lens_type}

OPTICAL PARAMETERS:
  Radius of Curvature 1: {lens.radius_of_curvature_1:.3f} mm
  Radius of Curvature 2: {lens.radius_of_curvature_2:.3f} mm
  Center Thickness: {lens.thickness:.3f} mm
  Clear Aperture: {lens.diameter:.3f} mm
  Material: {lens.material}
  Refractive Index: {lens.refractive_index:.4f}
  Focal Length: {f:.3f} mm          <- only if f = lens.calculate_focal_length() is truthy

Generated by OpenLens
```
- Line 3 is empty. That comes from `"=" * 60 + "\n\n"`.
- There is an empty line after `Lens Type:`, from the trailing `\n\n` on that line.
- There is one empty line before `Generated by OpenLens`.
- The file ends with `"Generated by OpenLens\n"`.
- The indentation under `OPTICAL PARAMETERS:` is two spaces.
- "Clear Aperture" prints `lens.diameter`, **not** `get_clear_aperture_1()`. Setting `clear_aperture_1=10` on a 25 mm lens still prints `Clear Aperture: 25.000 mm`.
- `name` and `material` are written verbatim, with no escaping or quoting. For example, `Fused Silica` stays unquoted and `<` stays `<`.

## 5. Side effects
- It creates or overwrites `filename`.
- It does not mutate `lens`, as far as this code shows. `calculate_focal_length` is in `lens.py`, which is not shown.

## 6. Branches and edge cases
- **Focal length line is present** when `calculate_focal_length()` returns a non-zero float. This includes negative values: a diverging lens gives e.g. `  Focal Length: -50.123 mm`.
- **Focal length line is absent** when it returns `None` or `0.0`. The line after `Refractive Index:` is then the blank line.
- **Infinite radius:** `f"{float('inf'):.3f}"` gives `"inf"`, so the line is `  Radius of Curvature 1: inf mm`. Whether `Lens` stores a flat surface as `inf` depends on `lens.py`, which is not shown. Build the expected string from `lens.radius_of_curvature_1`.
- **Negative radius** prints with a sign, e.g. `-100.000`.
- **Rounding:** `.3f` and `.4f` use Python's float formatting. `100.0` prints `100.000`; `1.5168` prints `1.5168`.

## 7. Rules from comments and docstrings
- The only docstring is "Export lens prescription (industry standard format)". It states nothing beyond the code.

## 8. Testing hints
- Use `tmp_path`, e.g. `p = tmp_path / "rx.txt"`, then call `PrescriptionExporter.export_prescription(lens, str(p))`.
- Read it back with `p.read_text(encoding="utf-8")`. Text mode normalises line endings, which matters on Windows, where `newline=None` may write `\r\n`. Do not compare raw bytes against `\n`.
- Build the lens explicitly, e.g. `Lens(name="T", radius_of_curvature_1=100.0, radius_of_curvature_2=-100.0, thickness=5.0, diameter=25.0, material="BK7")`.
- Compute expected values from the object rather than hard-coding physics:
  - `f"  Refractive Index: {lens.refractive_index:.4f}"`
  - `f"  Focal Length: {lens.calculate_focal_length():.3f} mm"`
  - `f"Lens Type: {lens.lens_type}"`. `Lens` may normalise or derive `lens_type` and `refractive_index`.
- Good exact assertions:
  - `lines[0] == "LENS PRESCRIPTION"`
  - `lines[1] == "=" * 60`
  - `lines[2] == ""`
  - `lines[3] == "Lens Name: T"`
  - `"  Radius of Curvature 1: 100.000 mm" in lines`
  - `"  Center Thickness: 5.000 mm" in lines`
  - `"  Clear Aperture: 25.000 mm" in lines`
  - `text.endswith("\nGenerated by OpenLens\n")`
- Check line order too, e.g. that `Material` comes right after `Clear Aperture`.
- To test the omitted focal-length line without relying on `Lens` physics, use a stub, e.g. a `types.SimpleNamespace` with all the attributes and `calculate_focal_length=lambda: None`. Then:
  - assert no line starts with `"  Focal Length"`
  - assert the line after `Refractive Index` is `""`
- Stub with `lambda: 0.0` to cover the falsy-zero case, and `lambda: -50.0` to check `  Focal Length: -50.000 mm` appears.
- The file is overwritten, not appended. Write twice with different names and assert only the second name is present.
- Pitfalls:
  - Do not assume `Lens` defaults; its constants are not visible.
  - Do not strip lines before comparing, because the two-space indent is part of the format.
  - Do not expect "Clear Aperture" to reflect `clear_aperture_1`.
